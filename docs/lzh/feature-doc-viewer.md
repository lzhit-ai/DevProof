## 2026-08-12 可信边界补强：GitHub 只读来源接入

### 本次修改

- GitHub 同步不再自行递增 `page` 参数，而是只跟随 GitHub 返回的 `Link: rel="next"` URL；因此兼容 REST 端点返回的 `page`、`after`、`before` 或 `since` 分页参数。
- 下一页链接会验证 HTTPS、`api.github.com` 主机和当前 `owner/repository` 路径；达到 50 页上限或中途失败时，持久化已读取页数和安全的分页位置，不记录请求头或密钥。
- 新增 `024_source_sync_pagination_cursor` 迁移，并将分页次数/续页位置返回给来源同步记录；历史同步记录默认保留为 0 页和空游标。
- GitHub Fine-grained PAT 仅以环境变量引用登记。GitHub API 在运行期注入 Bearer Header；Git 只读拉取仅在子进程环境中通过 `http.extraHeader` 注入 Basic Header，禁止交互、Git Hook 和重定向，Token 不进入 URL、数据库、日志或 API 响应。
- Git 仓库和外部来源连接可重新登记同一目标以更新“是否配置密钥引用”，并写入不含引用名和密钥值的审计事件。

### 当前状态

- 已完成 10 项最小自动化回归、迁移 SQL 生成检查和实际运行态部署：024 迁移已应用，API/Worker 就绪检查通过。
- 以公开大型仓库 `octocat/Spoon-Knife` 进行了真实只读同步。首次请求已按 GitHub 返回的 `after` cursor 连续读取 6 页；未配置 Token 时触达公共限流后，以 `SOURCE_RATE_LIMITED` 终态保存 `page_count=6` 和可追溯 cursor，而不是退回旧的 `page` 递增逻辑或伪报成功。

### 研发事项与交付变更关联

- 核验任务可以在创建时绑定一个研发事项，也可以在尚未固化正式记录时补充绑定。已经固化正式记录的历史任务保持“历史未关联”，不能事后改写归属。
- 新增事项—变更关联：一个关联只能指向一个已同步 PR 或一个冻结 Git 范围；同一事项对同一目标不会重复创建。冻结 Git 范围还必须来自已绑定同一事项的核验任务，避免跨事项误归因。
- 可以读取 GitHub Issue 时间线，将其中来自 PR 的交叉引用记录为平台确认的“事项—PR 关系”；这只说明二者被平台关联，绝不说明需求已实现或已交付完成。
- 提交人或管理员可以人工确认 PR / Git 范围归属，系统记录确认人、确认时间和审计事件。无关联的提交或 Diff 仍只是待归属开发活动，不能进入事项完成度。
- 事项可以关联既有资料版本，并标明它是验收条件、设计或计划资料；不复制资料内容。关联模型保留 `AGENT + CANDIDATE` 状态；候选 Agent 只在用户明确选择的同项目 PR 或同事项冻结 Git 范围中，以受控词元重叠规则提出候选，并冻结输入清单、输入哈希和规则版本。
- 候选不改变事项状态、完成率、核验结论或正式记录。用户确认后才会在同一关联记录上升级为 `USER + CONFIRMED`；这仍然只确认“事项—变更归属”，不证明需求或交付已经完成。

### 项目态势与研发总结

- 新增不可变的项目态势快照。它冻结事项版本、来源同步、已确认变更、正式交付记录、历史风险与待归属 Git 活动的结构化输入清单和哈希，再保存汇总、数据缺口与观察边界。
- 态势结果明确分别展示：计划事项、外部已声明完成、核验已确认、已拥有正式交付记录、已确认变更归属和已关联资料来源。没有有效计划分母时不展示完成率；即使有分母，也只展示核验覆盖，不把活动数量写成项目完成。
- 可以从一个态势快照生成日报、周报或迭代总结草稿。当前草稿是确定性事实汇总，未来外围总结 Agent 只能以此快照为输入扩写，不能越过其事实边界。
- 总结草稿可被“个人确认”固化为项目总结记录，用于后续回溯与再总结；它明确标记为 `PERSONAL_CONFIRMED`，不是独立审核或团队批准。交付报告发布后会依据冻结报告结果更新关联事项的核验状态。
- 项目态势可从一个已冻结态势快照固化为 `PROJECT_STATUS_SUMMARY` 外围运行，保留输入清单/哈希、输出、覆盖与限制，供后续总结或追溯读取；它不触发双核交付核验，也不改写项目总结记录。

### 安全与质量基线

- 新增 SHA 绑定的安全扫描输入：每次导入必须指定项目仓库、完整目标 SHA、扫描类型、扫描器/规则版本、覆盖说明、原始输出和结构化风险。支持 SAST、依赖、密钥、配置和 CI 输入，但不执行扫描器或仓库代码。
- 每条风险都可追溯到扫描输入、目标 SHA、扫描器和规则版本，并可由审核者或管理员标记为 `OPEN`、`ACCEPTED_RISK` 或 `REMEDIATION_CLAIMED`。整改声明仍需新扫描结果验证，系统不会称其为已修复。
- 可以从同一仓库、同一 SHA 的扫描输入生成不可变安全基线快照，冻结输入清单、风险、覆盖、缺失扫描类型与限制说明；无法混用不同 SHA 的结果。
- 基线可由审核者或管理员确认并固化为安全记录。记录只说明指定范围内的发现与覆盖，明确不会输出“项目绝对安全”或“发布通过”。未来安全 Agent 只能解释和归并已导入结果，不能无边界读取整个仓库。

- 安全解释现在以一个已导入扫描工件为唯一范围，返回该工件的 SHA、扫描器/规则、覆盖、风险严重度、处置状态与分类汇总，并同时返回观察和限制；它不读取工件之外的代码、不调用模型，也不输出安全通过结论。
- 质量趋势现在只比较严格可比的导入序列：同一仓库、扫描类型、扫描器名称与版本、规则版本。每个点保留 SHA、导入时间、内容哈希、发现数、严重度/状态汇总和覆盖；任一规则或扫描器变化都会形成新序列，而不是伪造风险升降。
- 安全基线运行只接收一个已冻结安全基线；质量趋势运行只接收至少两个严格可比的已导入扫描工件。两者均固化输入哈希、输出、覆盖和限制，独立于交付核验运行、双核、报告草稿、审批与发布。

### 自定义 Agent、工具与编排工作台

- 新增 Agent 功能块、工具授权、编排模板的数据模型、迁移、接口和工作台页面。
- 用户可创建外围 Agent，保存自定义 Prompt、输入/输出 Schema、参数 Schema 与已授权工具；自定义 Agent 现在只能归入 `SHARED` 外围能力，不能伪装成或替换两个固定核心。修改会从上一版本复制出一个新的版本，历史版本和已冻结运行不会被改写。
- 项目内可登记只读工具，并把工具授权给外围 Agent；密钥只保存服务端环境变量名称，不保存密钥值。
- `HTTP_QUERY` 已可在运行时执行：仅管理员能登记、仅允许服务端白名单内的 HTTPS 主机、仅 GET、禁止重定向、限制超时与响应大小。工具返回只记录为临时运行结果并写入运行事件与 Coverage，不会单独形成正式确认结论或正式证据。
- 工作台沿用现有浅色企业风格，并在“项目空间”左侧层级导航中加入“Agent 功能块”。页面支持查看双核、登记工具、创建自定义 Agent、基于上一版本编辑 Prompt/工具授权、停用自定义 Agent、选择能力块并调整模板顺序。
- 编排模板页会列出当前项目的真实核验任务及其绑定模板；提交人或管理员可为后续核验重新绑定可用模板。绑定只决定后续能力组合，不代表事项完成或交付已经通过。
- 自定义 Agent 的模型输出仅能提出证据关联建议；最终核验结论、审批、发布与输入快照仍由既有确定性规则和人工环节控制。
### 临时工具结果与正式证据边界

- `HTTP_QUERY` 的响应不再写入 `EvidenceItem`，而是以 `AgentToolExecution` 仅绑定本次分析运行保存。它保留响应哈希、受限摘录、定位信息、运行事件与 Coverage，但不是输入快照证据，也不能被模型输出当作可引用的 `evidenceId`。
- 外围 Agent 可以把临时工具结果作为审查线索；模型提示明确要求它不得引用、复述为事实或用其标识生成证据关联。模型调用审计中的允许证据列表也只包含本次冻结快照内的正式证据。
- Notebook 会单独展示“临时工具结果”，并提供“显式导入为补证”操作。导入由提交人或管理员触发，复制响应内容为具有来源链路的人工补证；之后仍须由用户选择并冻结到新的正式输入快照，才能成为可引用的正式证据。
- Citation Resolver、核验结果投影与报告草稿均拒绝历史或新产生的 `TOOL` / `HTTP_QUERY` 证据直接引用。已固化的历史记录不被改写；新报告不能再携带这类直接引用。

### 运行可见性与模型接入

- Notebook 会在当前项目内读取最新分析运行、冻结编排快照与真实核验结果；无真实运行时展示真实任务轮次与缺失条件，不保留演示数据。
- 分析运行结束后，若冻结模板启用了“报告草稿”能力块，Worker 会自动生成 DRAFT 报告、写入运行事件和审计记录；提交、审批、发布仍必须经过既有人工流程。
- 新增 DeepSeek 生成模型适配：配置 `GENERATION_PROVIDER=deepseek`、`DEEPSEEK_API_KEY` 后，可通过 Chat Completions 的 JSON 输出生成证据关联建议和证据问答结果；Compose 会将生成模型配置仅注入 API 与 Worker 容器。
- 正式运行只允许真实生成模型提供方（当前为 DeepSeek，保留 Gemini 扩展位）；未配置 API Key 时会返回明确的“模型未配置”错误，不能再用配置切换为 FakeModel。FakeGenerationModelAdapter 仅保留为离线测试夹具。
- 资料向量化已接入百炼 `text-embedding-v4` 的 OpenAI 兼容接口，固定请求 768 维向量以匹配 pgvector 列；生成模型与 Embedding 模型仍独立配置。Compose 可传入 DeepSeek、百炼及 Gemini 的真实模型配置，但本机当前为 DeepSeek 生成 + 百炼 Embedding。历史 FakeEmbedding 向量不会与百炼查询向量混合参与相似度检索，仍可通过关键词检索命中；需要向量检索时应重新上传资料生成新向量。
- Gemini Embedding 适配器也已统一为显式请求 768 维，作为真实供应商兼容性和本地验收通道；其 API Key 只允许存在于被 Git 忽略的本地运行配置中，示例、代码和文档均不保存密钥。
