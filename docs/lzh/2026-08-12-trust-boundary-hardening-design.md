# 可信边界补强设计

> 状态：方案已确认，等待本文档复核后进入实现。
>
> 范围：只补强已发现的正确性、接入与可运维缺口；不改变固定双核、冻结 Git Diff、人工审批和只读证据边界。

## 1. 目标与非目标

本轮目标是让现有的交付核验主链在以下情况下仍能保持可追溯、不可回退和可扩展：报告已发布、交付项关联变更、同步大型或私有 GitHub 仓库、Embedding 供应商迁移，以及运行失败后的定位与回归。

本轮不新增无边界全仓 AI 读码、安全扫描执行器、自动构建/测试/发布、任意网络写操作或可替换两个核心的自定义 Agent。

## 2. 固定约束

- `DELIVERY_VERIFICATION` 始终经过需求/验收核心、冻结 Git Diff 交付证据核心和确定性裁决；外围 Agent 只能是 `SHARED`。
- Git 只读，不能执行仓库代码、Hook、构建或测试；私有仓库凭据仅用于受控的只读 GitHub API/Git 请求。
- 快照、运行、已发布报告、审批和正式记录不可被新功能重写。
- 外部来源、凭据和工具运行都必须保留范围、版本、时间与错误摘要；不得存储或返回密钥明文。

## 3. 实施切片

### 切片 A：不可回退的交付核验状态

**解决问题**：已发布周期中的历史草稿仍可提交，可能把周期从 `PUBLISHED` 回退为待审核。

**设计**：

1. 将“报告可提交/可审批/可发布”改为同时校验报告状态、所属周期状态和当前报告归属。
2. 在状态转换事务中锁定核验周期；一旦周期为 `PUBLISHED`，拒绝该周期下所有报告的后续写状态转换。
3. 发布时仅允许当前经批准报告成为该周期的正式记录；失败不会改变报告、周期或记录。
4. 补充测试：旧草稿提交、并发提交/发布、重复发布均不能改变已发布周期。

**兼容策略**：历史已发布周期保持原样；不删除历史草稿，但其状态转换入口被锁定。

**提交**：`修复：锁定已发布核验周期`

### 切片 B：来源与交付归属完整性

**解决问题**：正式快照允许重复来源；同一项目内的交付项可错误关联另一仓库的 Git Diff。

**设计**：

1. `freeze_formal_snapshot` 在计算哈希前校验来源资料 ID 去重，重复即返回领域错误。
2. 对绑定交付项的核验任务，冻结 Git 仓库必须等于交付项来源仓库；没有可比来源仓库时拒绝创建交付核验，而不是猜测归属。
3. `DeliveryChangeLink` 再次校验仓库一致性，防止绕过任务入口直接创建错误关联。
4. 本轮不开放跨仓库豁免；若未来需要，由新的明确关联类型、理由、审核人和审计事件单独实现。

**提交**：`修复：收紧事项与Git范围归属`

### 切片 C：GitHub 只读接入完善

**解决问题**：大仓库 Issue 同步使用页码会在深页失败；私有仓库的 `credential_ref` 尚不能实际用于只读访问。

**设计**：

1. GitHub 客户端改为 Cursor 分页，持久化 `after`/`before` 游标、已读取数量和失败位置；既有小仓库的成功同步语义不变。
2. 增加凭据解析器：`credential_ref` 只引用环境变量名，运行时读取值并传给 GitHub API 或 Git HTTPS 请求；日志、API 响应、同步记录和异常信息均只保留引用名或脱敏标识。
3. 首期凭据格式为 GitHub Fine-grained PAT，限制为所需私有仓库的只读 Contents、Pull requests 和 Issues 权限；接口保留 GitHub App 实现位，但本轮不实现 App 签名和安装流程。
4. Git 读取使用临时进程级凭据传递，关闭交互提示，不把 Token 写进远程地址、数据库、命令审计或仓库配置。

**验收依赖**：真实私有仓库联调需用户在本地忽略的环境文件中配置只读 Token；实现和静态测试不需要该 Token。

**提交**：`功能：完善GitHub只读来源接入`

### 切片 D：向量索引迁移与可检索性

**解决问题**：切换 Embedding 供应商后，不同模型的向量不能安全比较，历史资料会无声退化为仅关键词检索。

**设计**：

1. 将检索索引版本明确为供应商、模型、维度和向量化参数的组合；查询只比较同一索引版本的向量。
2. 新增受控的“重建活动检索索引”操作：以现有已就绪资料内容生成新索引版本，原始资料版本、正式快照和历史向量保持不变。
3. 项目在一个时点只选择一个活动索引版本用于语义检索；旧版本显示为历史/不可用/可恢复，不能被错误混查。
4. 查询结果返回使用的索引版本；无活动向量索引时明确说明，只保留词法检索结果。

**验收依赖**：默认百炼的真实全链路需在网络稳定的 Worker 上执行；不能用 Fake 模型替代正式验收。

**提交**：`功能：支持资料检索索引重建`

### 切片 E：回归与运行可观测性

**解决问题**：当前关键边界依赖一次性人工脚本验收，失败后的批量定位和稳定回归不足。

**设计**：

1. 建立后端自动化回归测试，覆盖切片 A-D 的领域规则、凭据脱敏和迁移兼容性。
2. 为同步、索引重建和运行增加统一失败码、重试信息、关联运行 ID 和耗时统计；不把这些统计写成业务结论。
3. 保留 HTTP 工具当前的默认拒绝策略；待用户提供受控 HTTPS 白名单地址后，再验收“成功调用 → 临时结果 → 人工导入补证 → 新快照”的完整闭环。

**提交**：`功能：补齐核验回归与运行观测`

## 4. 实施顺序与验收

顺序固定为 A → B → C → D → E。A、B 先封住正式结论的可信边界；C、D 扩展事实和检索能力；E 将已确认规则变成持续回归保障。

每个切片均按以下顺序交付：追加迁移（如需要）→ 领域服务与 API → 最小前端状态（仅存在新操作时）→ 自动化测试/静态检查 → 更新 `feature-doc-viewer.md`、`task_plan.md`、`findings.md`、`progress.md` → 单独中文 Git 提交。所有提交仅留在本地，不推送。

## 5. 风险处理

| 风险 | 处理 |
| --- | --- |
| 历史发布记录被新校验拒绝 | 只限制新的状态转换；读取和回放历史记录不变。 |
| 私有 Token 泄漏 | 仅环境变量引用、脱敏日志、无远程 URL 注入、无数据库持久化。 |
| GitHub API 分页契约变化 | 统一封装分页器并记录游标，模拟响应验证停止和续跑。 |
| 向量重建影响正式证据 | 索引是派生检索数据；不修改资料版本、快照或报告引用。 |
| 网络无法访问供应商 | 显式记录 `MODEL_UNAVAILABLE`，不伪造向量或检索成功。 |

## 6. 完成定义

本轮完成后，已发布交付结论不会被历史草稿回退；交付项不会误关联跨仓库 Diff；GitHub 可持续同步大仓库且具备安全的私有只读凭据通道；模型切换后可显式重建检索索引；关键规则有可重复执行的自动化回归覆盖。未配置私有 Token、未提供 HTTP 白名单或供应商网络不可达时，系统必须明确拒绝或标记未验收，而不是伪造成功。
